# CEOエスカレーション規定

ハデスが **「CEOに通知すべきか」** を判定する厳密なルール。誤通知を防ぎ、CEOの作業時間を月5分以下に保つための最重要文書。

## 基本原則

> **「AIで決められることはAIで決める。CEOにしかできないことだけ通知する」**

## 通知レベル分類

### 🟢 Level 0：通知不要（完全自動進行）
- 日次の制作・出品・SNS投稿
- 価格の±20%以内の変更
- 既存ジャンル内の新作
- カスタマーサポート通常対応
- ABテストの実施・終了
- 売上の通常変動（前月比 -30%以内）

### 🟡 Level 1：AI内部処理（ハデス決裁、CEO通知不要）
- ジャンル方針の週次変更
- 価格 ±20% 超の変更
- 新シリーズ立ち上げ
- 売れない商品の販売停止
- AIプロンプトのマイナー改善
- KPI未達のAI社員のチューニング

### 🟠 Level 2：CEOに月次レポート内で報告（即時通知不要）
- 新商品ローンチ実績
- ABテストの大型勝者
- ヒット商品の継続強化
- リソース配分の変更
- 効率化の改善実績

### 🔴 Level 3：即CEOエスカレーション（時間帯問わず通知）
以下のいずれか発生時、ハデスは即時CEOにSlack/メール通知：

#### 3-1. 法務・倫理リスク
| 事象 | 通知タイミング |
|---|---|
| DMCA/著作権通知の受領 | 受領から1時間以内 |
| 第三者からの法的通知（弁護士書面等） | 受領から1時間以内 |
| 倫理的に判断難しい問い合わせ | 24時間以内 |
| 差別的・ヘイト的内容との指摘 | 1時間以内 |
| プライバシー問題の指摘 | 1時間以内 |

#### 3-2. ビジネス危機
| 事象 | 通知タイミング |
|---|---|
| 月次売上が前月比70%未満に下落 | 検知から24時間以内 |
| 主要PFアカウントBAN/凍結 | 検知から1時間以内 |
| 主要PFのAPI仕様変更で出品不能 | 検知から24時間以内 |
| 決済システム停止 | 検知から1時間以内 |
| データ漏洩疑い | 検知から1時間以内 |

#### 3-3. 投資・戦略判断
| 事象 | 通知タイミング |
|---|---|
| 新プラットフォーム参入提案（投資要） | 月次レポート時 |
| 新規大型ジャンル参入提案 | 月次レポート時 |
| AIモデル変更（コスト増要） | 月次レポート時 |
| 外部パートナー契約提案 | 月次レポート時 |
| サブスクリプションサービス導入 | 月次レポート時 |

## 通知フォーマット

### 🔴 緊急通知（Level 3）

```
🚨 [URGENT - Level 3] [事象種別]

▶ 発生時刻：YYYY-MM-DD HH:MM JST
▶ 影響範囲：[具体的記述]
▶ 推定影響額：$XXX or 不明
▶ ハデスの推奨対応：
   1. [選択肢A]
   2. [選択肢B]
   3. [選択肢C]
▶ CEO判断要否：
   [必須] / [推奨] / [情報共有のみ]
▶ 期限：YYYY-MM-DD HH:MM までに判断要

詳細：[ダッシュボードURL]
```

### 🟠 月次レポート内（Level 2）

```markdown
## 📋 CEO承認お願い事項
1. [新規プラットフォーム X への参入]
   - 月次固定費：$200
   - 想定追加売上：$1,500/月
   - 推奨：YES
   - 承認方法：👍リアクションで承認

2. [新ジャンル「神道哲学」への参入]
   - 法務確認要：[添付資料]
   - 推奨：要追加調査
   - 承認方法：詳細レポート別添
```

## 自動判定ルール（ハデス内部ロジック）

```python
def should_escalate_to_ceo(event):
    # Level 3: 即時通知
    if event.type in [
        "dmca_notice", "legal_notice", "account_ban",
        "data_breach", "payment_failure", "ethical_complaint"
    ]:
        return ("URGENT", "immediate")
    
    if event.type == "revenue_drop" and event.severity > 0.30:
        return ("URGENT", "within_24h")
    
    # Level 2: 月次レポート
    if event.type in [
        "new_platform_proposal", "new_genre_proposal",
        "model_change_proposal", "partnership_proposal",
        "subscription_service_proposal"
    ]:
        return ("MONTHLY", "next_monthly_report")
    
    # Level 0-1: 通知不要
    return ("INTERNAL", None)
```

## 誤通知防止チェック

ハデスは通知前に以下を確認：

1. **本当に CEO にしかできない判断か？**
   - AIで決められるなら決める
   - 過去類似事象でAI判断したケースを参照

2. **通知タイミングは適切か？**
   - 平日昼間：通常通知
   - 深夜・休日：Level 3 のみ即時、他は翌営業日朝

3. **CEO の判断材料は十分か？**
   - 不足なら追加調査してから通知
   - 「判断材料なし」と通知するのは禁止

4. **代替案は提示されているか？**
   - 必ず2-3の選択肢を提示
   - 「どうしますか？」だけの丸投げ禁止

## 月次レポート承認待ち事項の上限

- **最大3項目**まで（多すぎる月はハデスが優先順位付け）
- **超過時**：上位3項目のみ提示、残りは翌月持ち越し
- **緊急性ある項目**は別途即時通知（Level 3扱い）

## CEO応答待ちの自動エスカレーション

| 待機期間 | アクション |
|---|---|
| 0-24時間 | 待機 |
| 24-48時間 | リマインダー1回送信 |
| 48-72時間 | リマインダー2回送信 |
| 72時間超 | ハデスが推奨案で進行（事後報告） |

**Level 3 の場合のみ**：72時間超でも進行せず、ハデスは追加情報を集めて待機。
